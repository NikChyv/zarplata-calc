# Калькулятор зарплаты «на руки → начислено» (Беларусь)

**Открыть: https://nikchyv.github.io/zarplata-calc/**

ITNIMAX. Один самодостаточный файл — работает и онлайн, и локально двойным кликом,
без интернета, без установки, без сборки.

Расчёт целиком выполняется в браузере: сервера нет, введённые суммы никуда не
передаются и нигде не сохраняются.

## Как обновить сайт

Правки в `index.html` → коммит → `git push`. GitHub Pages пересобирает страницу сам,
обычно за минуту. Перед пушем прогоняйте `node test.js`.

| Файл | Что это |
|---|---|
| `index.html` | Весь калькулятор: интерфейс, логика, ставки |
| `test.js` | Автотесты расчёта (Node.js), берут код прямо из `index.html` |

## Интерфейс

Слева ввод, справа результат: крупная итоговая сумма, полоса «из чего складывается
начисленное» и таблица-легенда с теми же цветами и суммами. Детализация налоговой базы,
порядок расчёта и оговорки убраны в раскрывающиеся блоки — на экране по умолчанию только
цифры. Тёмная тема включается автоматически по настройке системы.

Цвета сегментов проверены на различимость при дальтонизме и на контраст в обеих темах.
Порядок цветов в полосе менять не стоит — именно он обеспечивает различимость соседних
сегментов; если добавляете новый вид удержания, ставьте его в конец.

## Как обновить ставки

Всё, что меняется ежегодно, лежит **в начале `index.html`** в блоке
`<script type="application/json" id="rates-config">`. Логику расчёта править не нужно.

```json
{
  "year": 2026,
  "rates_valid_from": "01.01.2026",
  "employee":   { "fszn_rate": 0.01, "income_tax_rate": 0.13, ... },
  "deductions": { "personal": 216, "personal_income_threshold": 1308,
                  "child": 63, "child_enhanced": 120, "special_category": 306 },
  "employer":   { "fszn_pension_rate": 0.28, "fszn_social_rate": 0.06,
                  "belgosstrakh_rate_default": 0.006, "dpns_employer_match_max": 0.03 }
}
```

Суммы вычетов — в рублях, ставки — долей единицы (`0.13` = 13%).
Поле `rates_valid_from` выводится в шапке калькулятора — по нему сразу видно,
если после смены года ставки забыли обновить.

Конфигурация лежит внутри HTML, а не отдельным `rates.json`, намеренно: браузер
блокирует чтение соседних файлов при открытии страницы с диска (`file://`), и
внешний JSON сломал бы работу «двойным кликом» — главный сценарий использования.

## Порядок расчёта

Все удержания считаются **от начисленной суммы (Gross)**:

1. ФСЗН с сотрудника — 1% от Gross
2. ДПНС (Указ №367) — 1–10% от Gross, если сотрудник участвует
3. Доход, подлежащий налогообложению = Gross − ФСЗН − ДПНС
4. Налоговая база = п.3 − стандартные вычеты − социальные вычеты (не меньше нуля)
5. Подоходный налог = база × 13%
6. Профсоюзный взнос — 1% от Gross, **налоговую базу не уменьшает** (отдельное удержание)
7. **На руки = Gross − ФСЗН − ДПНС − подоходный налог − профсоюз**

Личный вычет 216 руб. применяется, только если сумма из п.3 не превышает 1308 руб.
Это **порог, а не плавное уменьшение**: при превышении вычет не применяется вовсе.

Расходы нанимателя (справочно, на «на руки» не влияют): Gross + 28% + 6% в ФСЗН +
Белгосстрах. Доплата нанимателя по ДПНС (столько же, сколько сотрудник, но не более 3%)
показана отдельной строкой и **не прибавляется к итогу** — она перераспределяется из
28% пенсионного взноса, а не начисляется сверху.

## Про обратный расчёт (важно)

Обратная задача решается подбором (goal seek), а не алгебраической формулой — при смене
ставок и появлении новых порогов ничего переписывать не придётся.

Существенная деталь: **функция «на руки от начислено» не монотонна.** В точке, где
облагаемый доход переходит порог 1308 руб., личный вычет пропадает целиком, и «на руки»
падает скачком примерно на 28 руб. (216 × 13%). Последствия:

- одна и та же сумма на руки достижима при двух разных Gross;
- часть сумм на руки не достижима вообще ни при каком начислении;
- **обычный бинарный поиск по всему диапазону в этой зоне даёт завышенный Gross** —
  в тесте расхождение доходит до 32,61 руб. переплаты нанимателя на одном сотруднике.

Поэтому диапазон делится на два отрезка (до порога и после), на каждом функция
возрастает, и берётся минимальный Gross, дающий нужную сумму на руки. Граница порога
находится численно — при добавлении новых порогов достаточно дописать их в список
в функции `grossFromNet`.

Если точная сумма на руки недостижима, калькулятор берёт ближайшее значение «не меньше
цели» и честно пишет расхождение до копейки — молча округлять в такой задаче нельзя.

## Тесты

```
node test.js
```

Тест не дублирует логику, а вытаскивает её из `index.html`, поэтому не разъедется с
рабочим кодом. Что проверяется: контрольные примеры прямого расчёта, поведение порога
1308 руб. с двух сторон, разрыв функции, выбор правильной ветки при обратном расчёте,
расходы нанимателя, граничные случаи, и сплошная сверка обратного расчёта с перебором
Gross с шагом в копейку (~1800 целевых сумм).

**Запускайте после каждого обновления ставок** — контрольные суммы в тестах жёстко
привязаны к ставкам 2026 года, и при их смене ожидаемые значения в `test.js`
нужно пересчитать вместе с конфигом.

## Что сознательно не входит в первую версию

- Налог на сверхдоходы 25%/30% (годовая декларация при доходе свыше 350 000 руб.)
- Имущественные вычеты (нужна проверка права на вычет — отдельная логика)
- Удержания по исполнительным листам (алименты и т.п.)
- Внешние совместители и работающие по ГПХ — это отдельные калькуляторы

## Перед использованием в работе

1. Сверить ставки и суммы вычетов с действующей редакцией НК на текущий год.
2. Уточнить ставку Белгосстраха для конкретного клиента — она зависит от класса
   профессионального риска и не одинакова для всех. В поле стоит 0,6% как значение
   по умолчанию, но это не универсальная ставка.
3. Прогнать 2–3 реальных расчётных листка через прямой режим («знаю начислено») и
   сверить с расчётом в бухгалтерской программе.
